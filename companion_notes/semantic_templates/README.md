# Semantic templates: Index

**What this folder is.** Notes on building semantic templates into the conservative language models of the Semantic Simulation framework: the mathematics of where and when templates can be found, and the measurements that test it, one topic per file. The programme's plan and its Doi–Peliti formulation stay at the top level of `companion_notes/` (their links are frozen in the book); new notes on the programme go here. (Index written 2026-11-24.)

## Terminology for the matchers

Settled on 2026-11-27 at the author's request, after the wording of earlier notes caused confusion. Notes written before that date are worded to match.

- **The geometry matcher** is the one machine every template test since [Template_Matcher_From_Geometry.md](Template_Matcher_From_Geometry.md) uses: whitening by ordinary text, the cosines and lengths between a premise's particles, relational coordinates, the connective's position, one Gaussian cloud per kind of premise in a small discriminant subspace (a template is the set of its kinds' cloud centres), and the 1% false-fire rule. It never reads which word a particle is.
- **A reading** is the geometry matcher fed one kind of particle vector. Everything else is identical; the particle count and the subspace dimension are chosen per reading by the same search on development premises.
  - **token identity** (lex): cosine 1 for the same token, 0 otherwise; no learned vector ([Lexical_Baseline.md](Lexical_Baseline.md));
  - **the embedding** $h^{(0)}$; "the embedding matcher" is short for the geometry matcher fed the embedding ([The_Embedding_Template_Matcher.md](The_Embedding_Template_Matcher.md));
  - **a layer state** $h^{(\ell)}$, the state after $\ell$ layers; "the early state" is the state after layer 0 ([Early_State_Matcher_Runner_Up.md](Early_State_Matcher_Runner_Up.md));
  - **a displacement** $D_{\ell}$, what layer $\ell$ moved a particle by;
  - **a well frame** $W_{\ell}$, a particle's position among layer $\ell$'s wells (shares, radii, stiff coordinates and their change; [Template_Matchers_on_the_Dynamics.md](Template_Matchers_on_the_Dynamics.md), §2).
- **Joint readings** feed several vectors side by side: **states** (every layer state after layer 0), **path** (every displacement), **wells** (every well frame).
- **Layer readings** are the readings of the trained layers: states, displacements, well frames. **Dynamics readings** (in older notes "dynamics matchers") are the displacements and the well frames, which exist only because the forces act.
- **Names in older notes.** "The geometry-only matcher", "the first matcher" and "the earlier matcher" mean the geometry matcher as first run, fed the layer states $h^{(1)}$ and $h^{(2)}$ with the embedding as reference ([Template_Matcher_From_Geometry.md](Template_Matcher_From_Geometry.md)). "Matcher A" and "matcher B" are the path and the wells of [Template_Matchers_on_the_Dynamics.md](Template_Matchers_on_the_Dynamics.md).
- **Not the geometry matcher:** the frozen seven-node figure of [Logical_Forms_as_Geometric_Figures.md](Logical_Forms_as_Geometric_Figures.md), an earlier reader that compares the shape of an argument's node points with a frozen shape per form; and the **hybrids** of [Hybrid_Template_Matchers.md](Hybrid_Template_Matchers.md), which combine readings (step 0) or add a fitted gate (step 1a) or metric (test 3).
